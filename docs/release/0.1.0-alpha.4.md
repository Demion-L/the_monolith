# MONOLITH `0.1.0-alpha.4` — Release Notes

**Status:** alpha, release candidate — **not published**. MONOLITH is experimental
and **not production-ready**. Changes are relative to `v0.1.0-alpha.3`
(`4a24f1a`). Publication, tag and dist-tags are decisions of the owner.

## Improvements

- **State consistency after finalization (FIN-002).** `monolith finalize plan|apply`
  report a read-only `consistency` block (`CONSISTENT` / `INCONSISTENT` /
  `NOT_VERIFIED`, also in `--json`), computed with the same rules as
  `monolith brief`. Documents that finalization does not write (e.g.
  `roadmap-index.md`) get an advisory remediation; nothing is edited and the
  plan/apply status, digest and exit codes are unchanged.
- **Independent knowledge attribution (KA-001).** `monolith idea add --path <document file>`
  registers the exact document files of a knowledge artifact that belongs to no work
  item. A commit naming such a valid `IDEA-NNN` (judged in the commit's own tree) and
  touching only those files is *explained* in `Freshness` and `brief --reconcile` (which
  shows the declared paths) without touching the active story, missions or roadmap.
  Directory prefixes, non-document files (only `.md .mdx .markdown .adoc`), well-known agent-instruction file names, hidden/dependency directories and anything inside the MONOLITH root are not
  accepted (A4-SEC-03; a deny-list, not a proof that a document is harmless). Attribution explains a commit; it is not approval or review.
  See ADR-023 (whose text predates the narrowing; see Governance notes).
- **Semantic terminal output (CLI-UX-001).** Status words are tinted (green / yellow /
  red / grey; purple headings) in `validate`, `brief`, `brief --reconcile` and
  `finalize` — only on an interactive terminal. `monolith ui` prints `Status: READY`,
  the URL on its own line, and how to stop.

## Bug Fixes

- **FIN-001 capsule formatting.** The capsule was compared byte-for-byte while its
  layout lacked the blank line after headings that Prettier adds, so a formatted,
  unchanged capsule produced a conflict on the next `finalize plan`. New capsules are
  formatter-stable; an existing capsule that differs only in line endings, trailing
  whitespace, one blank line after a heading or trailing blank lines is recognised as
  already finalized (and never rewritten). Every other difference is still a conflict.
  The comparison is context-aware (A4-FIN-01): code fences, indented code, HTML comments,
  YAML frontmatter and Markdown hard line breaks are compared as written.

## Security Hardening (independent audit `MONOLITH-ALPHA4-AUDIT-001`)

- **Git evidence parsing (A4-SEC-01, A4-SEC-04).** The freshness check no longer splits
  `git log` text on control characters. Commit metadata and file lists are read with
  `-z` from separate commands, ids and dates are validated, the commit list is
  cross-checked with `git rev-list`, and unparseable output is `UNKNOWN`. Whitespace-only
  and other unusual file names are no longer dropped.
- **Offline, read-only git (A4-SEC-02).** Lazy fetch is disabled
  (`GIT_NO_LAZY_FETCH=1` and `GIT_ALLOW_PROTOCOL=none`): in a partial clone a missing blob
  leaves `UNKNOWN` instead of contacting the promisor remote, writing to the object
  store or running the remote's configured program. `-c protocol.allow=never` alone was
  tested and does **not** prevent this. Blob reads check size first (256 KiB cap).
- **Bounded work (A4-SEC-05).** A commit subject naming more than 8 ideas is refused with
  no git call; at most 64 registration reads happen per run.
- **Shallow clones and merges (A4-SEC-06 / L6).** A shallow clone is now `UNKNOWN`
  (`GIT_HISTORY_SHALLOW`); changes made inside a merge commit are read as activity.
- **CLI (A4-CLI-01, A4-CLI-02).** `--path` is documented under `idea add`;
  `mission checkpoint` rejects unknown options; `monolith ui` again prints
  `MONOLITH Mission Control: <url>` as its first line.

## Compatibility

Verified by tests: old idea files parse and serialise unchanged; ideas without `paths`
attribute nothing; capsules written by alpha.3 are recognised; plan digests do not
include the new `consistency` field or the capsule layout; `--json` output only gains
a field; exit codes unchanged; `NO_COLOR`, pipes and `--json` are free of ANSI.
Not verified: behaviour on real consumer projects (STC, Second Brain were not touched),
Windows / case-insensitive filesystems, a Prettier version other than 3.3.3, and
Prettier configurations other than defaults.

## Migration Notes

None required. To use independent knowledge: `monolith idea add ... --path docs/x.md`,
commit the idea together with a state-document update, then name `IDEA-NNN` in the
subject of commits that touch only those paths.

## Known Limitations

- Capsule text you put into the proposal is passed through as-is; Prettier rewrites of
  that text (e.g. `*` bullets) are not covered.
- A roadmap row `IN PROGRESS` while no story is active is not reported (no contract
  defines it as an inconsistency).
- The commit that registers an idea is ordinary activity until the next state-document commit.
- Git history limits (all fail towards `UNKNOWN`/activity, none is a proof of completeness):
  the check reads at most 500 commits after the last state update; the last state update
  is `git log -1` over the state documents, so history simplification across merges can
  select a different baseline than a human would; replace refs are ignored, legacy grafts are not separately verified. A clean merge shows no changes of its own, its merged commits are
  examined individually.
- Offline guarantee verified with git 2.53 on Linux against a local partial clone with a
  hostile `remote.origin.uploadpack`; other git versions, Windows and case-insensitive
  filesystems (macOS default) are not verified.
- A hard-linked residue of a capsule is diagnosed, not prevented (accepted limitation, L3).
- Idea files with a `paths` field written before this narrowing keep working but attribute
  nothing if a path is a directory prefix, source file or inside the MONOLITH root.
- Colour is not enabled by `FORCE_COLOR`; `monolith ui --open` is not implemented.
- The independent reviewer was an AI sub-agent of the same session family (fresh
  context, not an independent human or model vendor).

## Security Notes

Durable State security statements of alpha.3 are unchanged (Criterion 23 closure is not
a claim of full security acceptance). The freshness check runs only read-only git commands
(`rev-parse`, `log`, `rev-list`, `diff-tree`, `cat-file`; no shell), with lazy fetch and every
transport disabled, no LLM and no new write path. Git rename detection is disabled
(`--no-renames`), so moving files out of protected areas cannot be hidden, and submodule pointer changes are listed regardless of `.gitmodules`. These
properties are exercised by regression tests against real git (`git-hardening.test.ts`,
`ka001.test.ts`); they are not a security audit result.
