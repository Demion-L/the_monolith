# MONOLITH `0.1.0-alpha.3` — Release Notes

**Status:** alpha. MONOLITH is experimental and **not production-ready**. The API
and CLI may change without notice.

Install: `npm install -g @latysh-development/monolith@alpha`

Changes are listed relative to `v0.1.0-alpha.2`. Only changes recorded in the
commit history between `v0.1.0-alpha.2` and this release are listed.

---

## Update and finalize-story skill

### Legacy `finalize-story` compatibility and migration (DOGFOOD-002)

`monolith update` now classifies the installed `finalize-story` skill:

- **missing** — the current template is added;
- **byte-identical known legacy template** (SHA-256 registry verified against
  the `v0.1.0-alpha.0` … `v0.1.0-alpha.2` tags) — replaced with the current
  template;
- **edited** — never overwritten.

The template now describes the flow Proposal → `finalize plan` → READY + digest
→ Owner Approval → `finalize apply` → Verification and forbids manual
finalization. This is an **instruction-level** rule for agents; it is not
runtime-enforced.

### Fail-closed handling of unknown customized skills (DOGFOOD-005)

A customized `finalize-story` skill used to be classified SKIP when it merely
mentioned `monolith finalize plan` / `apply`, so an update could be reported
COMPLETE although the file might still allow manual finalization. Any
`finalize-story` skill that is neither the current template nor a known legacy
template is now a **CONFLICT**: it is kept byte-for-byte, the integration is
reported INCOMPLETE, and `monolith update --apply` exits with code `2`. The
owner must reconcile the file manually.

## Project state: Brief, Freshness, Reconcile, DOCSYNC

### Brief / Freshness identity consistency (PSC-002)

- Freshness reads the active story from the structural `**Story:** <id>` field,
  the same way DOCSYNC does.
- Exact `IDEA-NNN` ids are treated as ideas, not as work items.
- An unreadable active-story identity is reported as `UNKNOWN`, not `STALE`.
  Confirmed contradictions are still reported.

### Markdown section boundary hardening (PSC-002, PSC-004)

- Fenced code blocks and HTML comments in `active.md`, `roadmap-index.md` and
  `story-index.md` are ignored when reading state.
- Current Story section selection ignores headings inside code fences and HTML
  comments. Multiple real Current Story sections are treated as ambiguous and
  are not read.
- Brief, Freshness, Reconcile and DOCSYNC share one Markdown-context helper.

### State reconciliation reliability (PSC-004)

- Recorded text excludes fenced and commented text, so `UNRECORDED_WORK`
  detection (`monolith brief --reconcile`) is no longer satisfied by ids that
  appear only inside code fences or comments.
- An unbolded leading id is no longer accepted as a confirmed active-story
  identity.

### DOCSYNC ambiguity handling (PSC-004, PSC-004A)

- DOCSYNC section writes and expected-state checks use the same structural
  view as the Brief.
- A Current Story section that says "No active story" **and** contains a
  structural `**Story:**` field is a contradiction: the Brief reports it as
  `unknown` with a `STATE_CONTRADICTION` (Freshness `STALE`, never a confirmed
  `none` and never `FRESH`); DOCSYNC refuses the identity — `finalize plan` is
  `NOT_READY`, `finalize apply` is `REFUSED`, nothing is written.
- An expected state of "none" now requires that no structural `**Story:**`
  field is present at all (valid, duplicate or malformed).
- Plain "No active story" and plain `**Story:** <id>` behave as before.

## AI Working Chat Context (MONOLITH-CHAT-CONTEXT-001)

`monolith init` now creates `<monolithRoot>/context/MONOLITH-CHAT-CONTEXT.md`,
a project-independent English document to paste into an external AI working
chat. It describes MONOLITH's capabilities, project memory, workflow,
guarantees, limitations and a working agreement. It is a template file only:
no runtime change and no new dependency. An existing file is never overwritten.

Projects initialized with an earlier version do **not** receive this file from
`monolith update`; copy it from the template as described in the README.

## Mission Control UI (`monolith ui`)

Shipped in `dist/ui/` of the package.

- **UI-003A appearance polish:** Cosmic Glass is the default skin (an explicit
  Classic choice is preserved); the Appearance switcher moves to the top of the
  sidebar; the viewport reserves the scrollbar gutter to avoid horizontal
  layout shift.
- **UI-003D typography and branding:** typography polish, the MONOLITH mark in
  the side navigation, and favicons / Apple touch icon.

Verification status for this release: the packaged UI was smoke-tested from
the installed tarball (server starts on `127.0.0.1`, serves `index.html` and its
assets over HTTP, stops cleanly). No visual or cross-browser review was
performed as part of the release.

## Known limitations

- **Not production-ready.** Alpha software; formats and commands may change.
- **Instruction-level rules are not runtime-enforced.** The finalize-story flow
  (Owner Approval before `finalize apply`, no manual finalization), cognitive
  modes and other protocols are followed by agents by instruction. MONOLITH
  cannot prevent an agent or a person from editing files directly.
- **Concurrency / TOCTOU.** This release does not eliminate concurrency or
  time-of-check/time-of-use risks between `finalize plan`, owner approval and
  `finalize apply`, or between concurrent writers of the same files.
- **Customized `finalize-story` skills** are reported as CONFLICT and must be
  reconciled manually; their compatibility is not verified automatically.
- **Chat Context is not delivered by `monolith update`** to existing projects.
- **Markdown parsing is structural, not a full CommonMark parser.** Edge cases
  outside the covered patterns (fences, HTML comments, `**Story:**` fields) may
  still be read differently than a human expects.
- **UI** was smoke-tested only (see above); it is a local, read-oriented view
  bound to `127.0.0.1`.
- **Test stability.** One multi-process Durable State test has previously been
  observed to be unstable between runs. It passed in the alpha.3 regression run;
  its cause is not established and it is not fixed in this release.
- **`latest` dist-tag** still points to `0.1.0-alpha.0`: `npm install` without
  `@alpha` installs that older version.
- `docs/release/alpha-installation.md` still contains pre-publication wording
  from `0.1.0-alpha.0`; it was not rewritten in this release.

## Not fixed in this release

- No changes to Durable State or the Coordinatorium (`monolith durable`,
  `monolith mission`); they remain experimental.
- No runtime enforcement of owner approval or of the finalize-story skill
  contract was added.
- Concurrency and TOCTOU risks listed above remain open.
