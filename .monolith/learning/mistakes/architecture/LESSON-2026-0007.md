# Lesson: a new scaffold write path must consume the same list the preflight conflict check consumes

## Mistake

`src/init/scaffold.ts`'s `createEmptyDirs()` wrote 10 `.gitkeep`
placeholders via `writeFileSync(path, '')` with no existence check, while
`planScaffoldConflicts()` — the function the fix/init-safety story
(`a345e5a`) introduced specifically so no write happens against an
existing file — walked only the template directories and the AI-tool
instruction file. The two never shared a source list, so the `.gitkeep`
paths were invisible to preflight: a pre-existing, possibly non-empty
`.gitkeep` was silently truncated on init or re-init, exactly the class of
bug `a345e5a` was written to close everywhere else.

## Root Cause

The overwrite-safety contract ("refuse before writing, never partially
scaffold") was enforced per-write-path by independently re-deriving each
path list, not by a single shared list every write path and the preflight
check both read from. Adding a new write path later (here, one that
predated the safety story and was never retrofitted into it) had no
structural forcing function requiring it to also appear in the conflict
check — the omission compiled, tested green (no test exercised a
pre-existing `.gitkeep`), and shipped.

## Prevention

When adding or reviewing any write path inside `scaffoldInstance`
(or an equivalent generate-into-existing-directory flow elsewhere), check
that its target path(s) are derived from the *same* list/function that the
corresponding preflight conflict check consumes — never compute the
written paths and the checked paths from two separately-maintained
sources, even when the second source looks like "just a few extra
paths." If a new write path is deliberately exempt from the conflict
check (like `state.json`), that exemption must be explicit and named at
both call sites, not an silent absence from one of them.
