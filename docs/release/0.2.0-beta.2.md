# MONOLITH `0.2.0-beta.2` — Release Notes

**Status:** **DRAFT — NOT PUBLISHED.** The version in `package.json` is still `0.2.0-beta.1`; no tag, npm publish or
GitHub Release exists for `0.2.0-beta.2`. MONOLITH is experimental and **not a stable production release**.

Changes are relative to `v0.2.0-beta.1` (`47d9a6c`). Requires Node.js >= 20. Install after publication:

```bash
npm install -g @latysh-development/monolith@beta
```

## Highlights

- **Development History** — Mission Control shows missions, checkpoints and a timeline as recorded in the operational
  state; nothing is inferred.
- **Knowledge Lab** — read-only Ideas and Hypotheses with search, status filter and details.
- **Governance Check** — `monolith governance check [--json] [--strict]`: read-only integrity diagnostics over the
  existing read model (roadmap, active story, story index, capsules, ADRs, hypotheses, missions, ideas), including
  Mission→Story consistency (`MISSION_STORY_UNKNOWN`, `MISSION_ACTIVE_ON_FINALIZED_STORY`).
- **Claude Code hooks (opt-in)** — `monolith hook session-start | stop | pre-compact | print-config`. Non-blocking and
  read-only; nothing is installed unless you copy the printed snippet.
- **Session context recovery** — the SessionStart packet is bounded, names the source of every line and says `UNKNOWN`
  where nothing is recorded.
- **Verification evidence** — `monolith evidence run | report | list`. `run` executes the argv itself (no shell) and
  records only the exit status (OBSERVED); `report` records a statement (REPORTED, not verification). VERIFIED is
  computed: an OBSERVED pass whose revision still equals HEAD on a clean working tree.
- **Autonomous handover** — `monolith handover check [--json] [--strict]` and Mission Control **Handover** section
  (`GET /api/handover`): what was done, what is verified, what is stale or unknown, what needs the owner. Statuses:
  READY FOR REVIEW / REVIEW WITH ISSUES / INCOMPLETE / UNKNOWN. It is a reviewability status, never "production-ready".

## Upgrade notes

- **No migration.** Durable State stays schema v3; no existing file format changed; `finalize` (digest, plan/apply,
  preconditions) is unchanged. A project without the new commands' data simply reports `UNKNOWN`/`INCOMPLETE`.
- New files appear only when you use the feature: `<monolithRoot>/memory/long-term/verification/EVD-NNNN.json`.
- `monolith update` does not add the "Autonomous Development: Reporting Discipline" section to an existing
  `CLAUDE.md`; it is in the `init` template only. Copy it manually if wanted.
- Existing Claude Code hook snippets (SessionStart/Stop only) keep working; re-run `monolith hook print-config` to add
  PreCompact.

## Compatibility

Verified from a locally built tarball in a clean project: `init`, `validate`, `governance check`, `handover check`,
`brief`, `evidence run/report/list`, all hooks, and `monolith ui` with `/api/handover` (GET 200, POST 405).
Read-only smoke on a snapshot copy of a real external project (14 missions, 9 checkpoints, 10 stories, 3 ADRs, 4 ideas):
all counts match the source documents.

## Known limitations

- **Evidence is not tamper-evident.** The CLI has no edit/delete command, but a hand-edited or deleted `EVD-*.json` is
  not detected by `handover check` (verified by experiment). Git history is the only audit trail. No hash chain by design.
- Evidence has no "superseded" concept: a FAILED record cannot be cleared by a later pass.
- Secret redaction of command lines and notes is best effort; do not put secrets on a command line.
- In a checkout with untracked files (e.g. `ui/images/`) recorded evidence is UNKNOWN (`REVISION_MATCH_DIRTY`), not
  VERIFIED — by contract: a dirty tree is never ignored.
- "Awaiting review" is read only from `story-index.md`; a story does not point to missions, so "story names a missing
  mission" is not checked.
- Phase statuses must be exactly PLANNED / IN PROGRESS / COMPLETE / NOT DEFINED; a roadmap that writes `COMPLETED`
  yields `PHASE_STATUS_UNRECOGNIZED` warnings (strict vocabulary, nothing is guessed).
- PreCompact is an instruction channel for the compaction summary, not a persistence guarantee.
- Visual QA was done on desktop width only; mobile viewport is unverified. Windows is unverified.
- Mission Control is read-only, loopback-only and unauthenticated. Durable State and the Coordinatorium are experimental.
- Check-then-use races (SEC-001B.3) are not defended, as elsewhere.

## Release checklist (owner-run; nothing below has been done)

1. Confirm the version: `npm view @latysh-development/monolith dist-tags versions` (at preparation: `beta` =
   `0.2.0-beta.1`; `0.2.0-beta.2` unused).
2. Version bump in `package.json` to `0.2.0-beta.2`; flip this document to PUBLISHED when done (set tag/commit).
3. `corepack pnpm run build && corepack pnpm run build:ui`; commit synced `dist/`.
4. Gates: `typecheck`, `typecheck:ui`, `check:skills`, `check:build-integrity`, `check:package`, `test`, `test:ui`.
5. `npm pack`; install the tarball in a disposable project; run `init`, `validate`, `governance check`,
   `handover check`, `evidence run`, hooks, `ui`.
6. Release commit; **push** `main` and wait for CI.
7. **Tag** `v0.2.0-beta.2` on the release commit (never move `v0.2.0-beta.1`).
8. `npm publish --tag beta` (never `latest`); verify `npm view ... dist-tags`.
9. GitHub Release for the tag.
10. Post-publish: `npm install -g @latysh-development/monolith@beta` in a clean prefix; `monolith --version`; `init`+`validate`.
