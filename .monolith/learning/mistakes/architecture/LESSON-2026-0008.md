# Lesson: sanitize at the output boundary, and test with a model where every string is hostile

## Mistake

`monolith brief` output is read by AI sessions. Mission titles, checkpoint
summaries and doc titles were escaped with `sanitizeSingleLine`, but
document `id`, document `path` (a filename), `monolithRoot` and provenance
pointers were interpolated raw. A file whose *name* contained a newline
forged a real `Completeness: COMPLETE` line and a `## Fake` heading in
stdout; an ANSI escape in a frontmatter `id` reached the terminal raw.

## Root Cause

Sanitization was applied field-by-field to the fields the author thought of
as "free text", not to every string that originates in project files or
configuration. Paths, ids and provenance looked like system values, so no
one asked whether a project could control them. The tests also used one
hostile field at a time, so the unsanitized ones were never exercised.

## Prevention

For any renderer whose output is consumed by a model or a terminal: (1)
treat every interpolated string that is not a compile-time constant or a
validated enum as project-controlled and route it through the sanitizer —
review by grepping the renderer for `${` and checking each one; (2) add a
test that builds the model with the *same hostile value in every string
field at once* and asserts structural invariants (exactly one
`Completeness:` line, no forged headings, no raw control characters), plus
one end-to-end test with a hostile filename on a real directory.
