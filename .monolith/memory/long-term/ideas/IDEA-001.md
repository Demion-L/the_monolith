## Description

Context: When MONOLITH is connected to an existing project, the system creates empty memory templates, although the project already has a development history, architectural decisions, completed tasks and current progress.

Hypothesis: MONOLITH can help restore project context from existing sources: Git history, README, TODO, ADR, documentation and source code.

Potential capabilities:
- Detect existing development phases and stages.
- Reconstruct completed and active stories.
- Prepare a roadmap with verifiable completion criteria.
- Create retrospective summaries and story capsules.
- Keep references to sources and a confidence level for each conclusion.
- Detect contradictions and gaps in the project history.
- Prepare a bootstrap plan for owner approval.

Critical invariant: Retrospective reconstruction must not be presented as MONOLITH workflows that were actually executed. It is forbidden to create fictitious evidence, integrity/governance PASS, or records of checks that did not historically happen.

Origin: Real integration of MONOLITH into SupportOps Agent, where development has progressed to Safety & Policy, but the MONOLITH roadmap and story memory remain empty.
